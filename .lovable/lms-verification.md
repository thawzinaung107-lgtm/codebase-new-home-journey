## PASS — focused redirect regression (2026-11-13, 11:49 UTC)
- Reproduced the previous FAIL on both 1280×1800 and 390×844: two passes through `/dashboard`, `/payments`, `/devices`, `/redeem`, `/admin`, `/admin/settings`, `/admin/payments` after opening `/auth` produced **42 recovered page errors per viewport**, plus `MatchView/routeId` console errors. This was not an isolated redirect test.
- Small application fix: `src/routes/__root.tsx` selects the immediate child route ID and keys the existing `AuthProvider`/`Outlet` subtree with it. The public/protected boundary now replaces the exiting tree atomically; protected sibling routes retain the same key. Managed `_authenticated` gate, `ssr:false`, loaders, bearer middleware, server authorization, prices, approvals and data are unchanged. No error filtering, null guards in framework internals, artificial delays or global SSR disablement.
- Diagnosis: the partial SSR tree contains a pending client-only protected boundary; its client auth redirect removes a match while React can still hydrate the exiting tree. Installed `MatchView` and the served `@oj-start` runtime both dereference the cleared match. Auth initialization does not invalidate on `INITIAL_SESSION`; child loaders/preloading are not the cause of this anonymous redirect. Declared Router 1.170.41/Start 1.168.60 match Start's dependency requirements (different package version numbers are expected); no dependency changes were needed.
- Upstream evidence: [TanStack issue #8198](https://github.com/TanStack/router/issues/8198) and [departed-match fix proposal #8576](https://github.com/TanStack/router/pull/8576). The proposal was **open/unmerged** when checked. This is an app-level mitigation verified in the running preview, not a claim that the framework defect is fixed upstream or unique to the platform.
- Persistent strict regression: `python3 tests/browser/redirect_regression.py` against the existing localhost preview. **PASS desktop and mobile:** three passes per viewport, each protected hard entry followed by refresh (84 navigation/refresh checks total); existing injected-admin read views and protected sibling navigation; real Sign out button with only its remote logout request intercepted; Back, refresh and another complete protected-route pass; zero page/console errors, no private workspace/file input while anonymous, no horizontal overflow.
- **Security negative PASS:** student and admin read RPCs called without bearer, twice per viewport, return only `Unauthorized: No authorization header provided` with undefined result. Start serializes these errors in **HTTP 200 RPC envelopes**, not HTTP 401; the regression asserts the precise error and absent result, not a permissive status-only check. An initial malformed replay failed deserialization and was corrected; it was not counted as an auth-denial pass.
- **Tests/build PASS:** full `bunx vitest run`: 19 passed, 1 deliberately skipped mutating integration test. Automatic compilation reports build OK at 11:47:38 UTC; no manual duplicate build/typecheck. Content-route metadata remains unchanged and was inspected for leaf titles/description/OG/type/card.
